# Contributing

Contributions should improve defensive visibility, reliability, documentation, privacy, or testing.

1. Keep collection read-only and use documented Windows APIs.
2. Build with `build.cmd`; warnings are treated as errors.
3. Test with non-sensitive synthetic data.
4. Document new collected fields and their privacy impact.
5. Do not submit binaries, real triage reports, secrets, personal data, malware, exploit code, credential access, injection, evasion, or persistence creation.
6. Keep pull requests focused and explain the analyst use case.

By contributing, you agree that your contribution is licensed under the MIT License.
